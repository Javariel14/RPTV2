# E3C1 — Order Reconciliation Core continuity

## Base and scope

- Base branch: `main`; base commit: `9d238792def1b63be2d9611193ee40cf3127fb1b`.
- Working branch: `feature/e3c1-order-reconciliation-core`; implementation remains uncommitted.
- E3C0 concluded that E3B3 already owns approval, acceptance, and canonical Order creation, while E3B4 owns commercial cancellation/replacement. E3C1 only records and reconciles adapter-neutral external Order evidence.
- No vendor connector, API/UI transport, business Order number, payment, fulfillment, fiscal, or AI behavior is introduced.

## Implementation decisions

- One new forward-only migration: `20260929142613_e3c1_order_reconciliation_core.sql`, created with the Supabase CLI. Historical migrations remain unchanged.
- Unmatched intake stores tenant, workspace, market, source system, external identity, event times, raw hash, correlation, authority, and runtime actor without inventing a canonical Order UUID.
- A typed, immutable external binding links a scoped provider identity only to `rpt.cpq_order`, never to legacy CRM `rpt.commercial_order`.
- Versioned current projection and append-only events classify exact duplicate, stale, ambiguous, matched, and conflict behavior. Concurrent binding/resolution uses transaction-scoped key locking, row locks, expected version, and database constraints.
- Once bound, evidence reuses generic `rpt.source_observation` and `rpt.reconciliation_case`. The typed subject is `order`; an unmatched intake creates neither generic observation nor fake subject.
- Source authority remains separate from `order_reconciliation` actor capabilities, workspace permission, Market Lock, and canonical Order visibility. Official resolution requires independently authorized official source evidence and cannot modify approval, acceptance, Order money, or E3B4 lifecycle.
- The generic source-observation uniqueness is scoped by `domain_key` in the new migration so equal provider identity/hash may legitimately be evidence for distinct typed domains.
- Application operations expose structured E3C1 error codes for future transport without adding endpoints. Foreign object existence is not included in errors.
